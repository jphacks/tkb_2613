# 認可・IDOR（カテゴリ3）

[← 目次](README.md)

- 対象: みーつけた api（FastAPI） / commit df27bac
- 実施日: 2026-11-06 / ローカル実施・破壊的操作なし（実削除なし）
- 環境: モック(:8002, `MOCK_MODE=1`)。2つのセッション（A・B）を作り、Bから Aの診断結果を触れるかを実機リクエストで確認

## 判定

脆弱性なし。他セッションの診断結果を参照・操作する経路はなかった。

## テストの考え方

`simulate` / `delete` が対象にできるのは「そのセッションで最後に診断した投稿」だけ（`known = {p.post_id for p in diagnosis.posts}`）。セッションAで診断し、Bでは診断しない状態で、BからAの投稿を触れるかを見た。

## 結果

| # | テスト | 期待 | 実測 | 判定 |
|---|---|---|---|---|
| 隔離 | B（未診断）が、Aの診断済み投稿IDを simulate | 使えない | 409（Bに診断がない） | 合格 |
| 隔離 | B（未診断）が、同IDを delete | 使えない | 409 | 合格 |
| 前提 | A が自分の診断済みIDを simulate | 200 | 200 | 合格 |
| 境界 | A が自分の診断に無いIDを simulate | 422 | 422 | 合格 |
| 未認証 | Cookieなしで simulate / delete / diagnose | すべて401 | すべて401 | 合格 |
| 二重送信 | 同じ投稿の delete を10並列（モック） | 500/例外なし | 10件すべて200・ログにエラーなし | 合格 |

## 所見

- 診断結果は `SessionStore` にセッションID単位で保存される（`get_diagnosis(session_id)`）。他セッションのIDを知っていても、自分のセッションに診断が無ければ409で、他人の結果を借用できない。
- 診断後も、送ったIDが自分の診断の `known` に無ければ422。他人の投稿IDを混ぜて削除する経路はない。
- 投稿取得・診断・削除はすべてセッションの DID に紐づく（ハンドルやURLを外から指定する口は無い）。ルール「本人のアカウントだけ」を満たす。
- `at://` URI そのものの検証は [04-uri-validation.md](04-uri-validation.md) を参照。
