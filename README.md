# サンプル（プロダクト名）

[![IMAGE ALT TEXT HERE](https://jphacks.com/wp-content/uploads/2026/07/IMG_5316.png)](https://www.youtube.com/watch?v=piaNsc6ilBI)

作品名は「みーつけた」。Bluesky の自分の投稿を横断し、投稿文や写真の手がかりからどのような生活情報が推定されうるかを確かめる Web アプリです。現在のモック起動と確認手順は[環境構築の手順](docs/setup.md)、実装済みの API とイベントの範囲は[現行 API・SSE 契約](docs/api-sse-contract.md)を参照してください。

`make dev` のモックでは API は Bluesky のログイン先や AI モデルへ接続せず、固定の架空投稿を使います。架空投稿に含まれる写真 URL はブラウザから `cdn.bsky.app` へ画像リクエストを試みるため、写真だけ表示できない場合があります。

## 製品概要
### 背景(製品開発のきっかけ、課題等）
本名や住所を直接書かなくても、SNS の投稿文、写真、時刻、繰り返し現れる場所などは少しずつ手がかりになります。1 件ずつなら無害に見える内容でも、複数の投稿を組み合わせることで、生活圏、通勤先、日課、家族との関係などを推測できる場合があります。本人が投稿を一件ずつ覚えていても、長い履歴を横断して第三者の視点で読み直すのは簡単ではありません。

Hack Day 前は投稿前の写真 1 枚を塗って隠す案でしたが、2026 年 10 月 24 日 13 時に、文章と複数投稿を横断して本人が履歴を見直す案へ方向を変えました。単独の写真加工では扱えない「情報が別々の投稿に分散し、時間とともに組み合わさる」課題を中心に置くためです。診断対象はログインした本人のアカウントに限り、他人のハンドル名を入力して調べる機能や一括クロールは作りません。
### 製品説明（具体的な製品の説明）
利用者が自分の Bluesky アカウントにログインすると、API が本人の投稿を取得し、各投稿から観測できる手がかりを集めます。推理結果には、根拠として使った手がかりを結び付けます。削除候補を選んだ後は、実際に削除する前に仮に取り除いた結果を確認できます。Bluesky からの削除は、利用者が選択し、確認ダイアログで確定した場合に限ります。

現在の実装は、ログイン、本人投稿の取得、投稿単位の抽出、試作ルールによる結論、削除候補、仮除外の比較、確認後の削除までです。プロフィールの 16 項目を `found / weak / unknown` と確度・根拠でまとめる目標形式は未接続です。現状の推理属性は `station`、`active_time`、`routine` を中心とした試作です。
### 特長
#### 1. 特長1
投稿を一件ずつ独立に判定するのではなく、写真と本文から得た手がかりを投稿をまたいで確認します。手がかりは「何が見えたか・何が書かれていたか」という観測として扱い、職業や住所などの推論そのものとは分けています。
#### 2. 特長2
結論から使われた手がかりへ戻れるよう、同じ診断内の手がかり番号を根拠として保持します。これにより、モデルやルールの誤読を事実のように扱わず、推定のどこに根拠があるかを利用者が確かめられます。推定は断定ではなく、本人の特定や安全を保証するものでもありません。
#### 3. 特長3
投稿を大量に消すよう促すと、必要な記録まで失わせ、行動の負担も増やします。そこで、現在の試作推理で重要な結論を弱める候補を最大 3 件まで示し、選んだ投稿を仮に除いた場合の結果を先に表示します。実削除は利用者が確認したときだけ行い、削除後は残った投稿で診断し直せます。

### 解決出来ること
「個人情報を直接書いていないから大丈夫」と感じる利用者が、自分の投稿を組み合わせたときの手がかりと推論を見直す材料を提供します。投稿を消すこと自体を一律に勧めるのではなく、どの投稿がどの結論に関係したかを見たうえで、本人が判断できることを目指します。
### 今後の展望
現在は推理ルールとプロフィール表示が試作段階です。今後は、16 項目プロフィールの確度・状態・根拠と削除プランナーをつなぎ、削除前後でどの項目が不明になったかを評価できる形にします。評価には架空のデモ用アカウントを使い、削除前後に推定できた項目数などを測ります。測定前の精度や改善値は掲載しません。
### 注力したこと（こだわり等）
* 観測（投稿で見えた情報）と推論（そこから導いた仮説）を分け、結論から根拠へ戻れること。
* 本人の投稿だけを対象にし、削除判断を利用者に残すこと。投稿本文や写真の指示に従わせず、モデルに削除操作を任せないこと。
* 投稿を横断するリスクを伝えつつ、診断結果を断定や安全保証として見せないこと。

## 開発技術
### 活用した技術
#### API・データ
* Bluesky の本人認証と本人投稿取得は Python API が担当します。ブラウザから Bluesky へ直接接続せず、本人の DID にひも付くセッションで対象を限定します。
* FastAPI は投稿一覧、投稿ごとの手がかり、結論、候補プランを Server-Sent Events で順に配信します。手がかりは共通 Pydantic 型で受け渡し、推理結果は根拠となる手がかり番号を持ちます。
* 画像・本文の抽出器は vLLM の OpenAI 互換 API と PP-OCRv5 の HTTP サービスを利用できます。接続先にはチーム管理下のサーバーを設定し、既知の第三者 AI サービスを拒否するガードがあります。モックでは API から外部モデルへ接続しません。画像取得先も `cdn.bsky.app` に限定します。
* `data-prep/` は駅などの公開データを取得・変換します。データ本体はコミットしません。モックの基本起動に公開データは必須ではありません。

#### フレームワーク・ライブラリ・モジュール
* Web：Next.js App Router、React、TypeScript、Tailwind CSS
* API と共通型：Python、FastAPI、Pydantic、`common/` の共有スキーマ
* 手がかり抽出：OCR・VLM クライアント、投稿単位の抽出パイプライン
* 推理・評価：決定的な試作ルール、最大 3 投稿の貪欲な候補選定、pytest、Vitest、ruff、mypy、ESLint、TypeScript 型検査、GitHub Actions

#### デバイス
* Web ブラウザが動く PC。Windows は WSL2 上の Ubuntu を推奨します。モック起動に Bluesky アカウントや GPU サーバーは不要です。

### 独自技術
#### ハッカソンで開発した独自機能・技術
* 投稿を取得して診断するパイプラインは [`api/src/tkb_api/pipeline.py`](api/src/tkb_api/pipeline.py)、観測ルールは [`engine/src/tkb_engine/rules.py`](engine/src/tkb_engine/rules.py)、投稿削除の仮比較と候補選定は [`engine/src/tkb_engine/planner.py`](engine/src/tkb_engine/planner.py) にあります。
* API の SSE 契約、候補提示、仮除外、実削除の入力条件は[現行 API・SSE 契約](docs/api-sse-contract.md)、画面側の診断と根拠表示は [`web/src/components/diagnose/DiagnosePanel.tsx`](web/src/components/diagnose/DiagnosePanel.tsx) と [`web/src/components/conclusion-board/ConclusionBoard.tsx`](web/src/components/conclusion-board/ConclusionBoard.tsx) を参照してください。
* 実削除は取り消せません。画面で選択し、確認ダイアログで確定した投稿だけを本人の Bluesky アカウントから削除します。モックでは外部削除を行いません。
* Hack Day 前に用意した土台と当日実装の区別は[事前開発の記録](docs/pre-hackday.md)を参照してください。固定の架空データでの動作確認は実投稿に対する精度評価ではありません。
