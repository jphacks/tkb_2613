# みーつけた

「みーつけた」は、Bluesky の投稿を手がかりに、投稿を重ねたときにどんな生活情報が推定されうるかを本人と確かめる Web アプリです。

> **開発状況**：Hack Day 中の開発を進めています。現在動く範囲と、目標としている機能をこの README で分けて説明します。実装済み範囲はコードと [現行 API・SSE 契約](docs/api-sse-contract.md) に基づいています。

ローカルでのモック起動は[環境構築の手順](docs/setup.md)を参照してください。モックモードは架空デモの投稿を再生し、Bluesky や AI モデルへ接続しません。

## 製品概要
### 背景(製品開発のきっかけ、課題等）
SNS では、本名や住所を直接書かなくても、投稿文・写真・投稿時刻・繰り返し現れる場所などが少しずつ公開されます。1 件だけなら無害に見える情報も、過去の投稿と組み合わせると、通勤先や生活圏、日課、家族との関係といった個人に関する仮説につながることがあります。

この作品は「公開してよいか」を投稿前に一律で判定するのではなく、すでに投稿した本人が、自分の投稿を横断したときに見える手がかりと推論のつながりを確かめ、必要なら投稿を見直す体験を目指します。推定の正しさや実際の危険度は投稿内容・文脈に左右されるため、断定や安全の保証はしません。

Hack Day 前の「投稿前の写真 1 枚を塗って隠す」案から、2026 年 10 月 24 日 13 時に、文章と複数投稿を含めて本人の投稿履歴を振り返る案へ方向を変えました。1 枚の画像だけを直すより、情報が複数の投稿に分散し、時間をかけて重なる問題に向き合うためです。現在は Bluesky の本人アカウントを対象にする設計です。
### 製品説明（具体的な製品の説明）
利用者が自分の Bluesky アカウントにログインすると、アプリは本人の投稿を読み、投稿ごとの観測手がかりを集めてプロフィール上の推定と根拠を表示します。目指す診断の流れは「投稿を読む → 観測と推論の根拠をたどる → 推定を弱める投稿の削除候補を選ぶ → 本人の確認後に削除する → 残った投稿で再診断する」です。

投稿本文や写真に書かれた文字はデータとして扱い、そこに書かれた指示には従いません。削除をモデルに任せず、候補の選択と確認を利用者に求める方針です。
### 特長
#### 1. 投稿をまたいだ手がかりの確認
1 件ずつでは目立たない投稿文や写真内の情報を、投稿単位の観測として集め、複数の投稿を根拠に推論する設計です。
#### 2. 観測と推論を分け、根拠をたどる
「写真や文章に何が見えたか」と「そこから何が推定されたか」を別の段階で扱います。目標は、推定項目から根拠の投稿、写真内の位置まで確認できることです。
#### 3. 少ない投稿の見直しで効果を確かめる
推定を弱めるために見直す投稿をできるだけ絞って提案し、削除前後を比べる体験を目指します。削除は利用者が確認したときだけ行います。

### 解決出来ること
「自分は直接的な個人情報を出していないから大丈夫」と感じる人に、複数投稿を合わせて見たときに残る手がかりと推論の根拠を示し、投稿の見直しを考える材料を提供します。推定は誤りうるため、本人の特定や安全を保証するものではありません。
### 今後の展望
現行実装では、ログイン、投稿の取得、投稿単位の処理、手がかりと試作結論の表示までを確認できます。目標機能のうち、16 項目プロフィール、根拠を踏まえた削除プランナー、削除前後の再推定、実投稿の削除はまだ画面・APIにつながっていません。今後はこれらを本人の確認を中心とした一連の診断として仕上げ、架空デモアカウントで削除前後の推定項目数を評価します。実測結果が得られた場合に限り数値を報告します。
### 注力したこと（こだわり等）
* 推測を事実として表示せず、各結論を観測した手がかりへ戻れる構造にすること。
* 投稿を削除する判断は本人に残し、本人のアカウントだけを対象にすること。パスワードや診断内容を保存せず、写真・本文を第三者の AI サービスへ送らないこと。

## 開発技術
### 活用した技術
#### API・データ
* Bluesky の本人投稿を取得する API。通信は FastAPI 側に置き、画面から Bluesky へ直接接続しません。
* OCR と画像を読む言語モデルのクライアントは vLLM の OpenAI 互換 API と PP-OCRv5 の HTTP サービス向けです。接続先はチーム管理下のサーバーを想定しています。モック起動ではどちらにも接続しません。
* `data-prep/` は駅などの公開データを取得・変換します。データ本体はリポジトリへコミットしません。

#### フレームワーク・ライブラリ・モジュール
* Web：Next.js App Router、React、TypeScript、Tailwind CSS
* API：Python、FastAPI、Pydantic。Python の共通データ型は `common/` に置きます。
* 開発・検証：uv workspace、pnpm、pytest、Vitest、ruff、mypy、ESLint、TypeScript の型検査、GitHub Actions

#### デバイス
* Web ブラウザが動く PC。Windows では WSL2 上の Ubuntu を推奨します。GPU サーバーはローカルモック起動には不要です。

#### HackDay期間中に作成したもの
現時点での実装済み範囲は、本人ログイン、本人投稿の取得、投稿ごとの処理、手がかりと試作結論の SSE 配信です。API は投稿一覧、投稿ごとの手がかり、結論の順でイベントを送り、結論から同一診断内の手がかり番号へ戻れるようにしています（[診断パイプライン](api/src/tkb_api/pipeline.py)）。試作エンジンの R1〜R3 は場所と投稿時刻などの手がかりを使う決定的なルールで、16 項目プロフィールへの対応づけは未実装です（[推理ルール](engine/src/tkb_engine/rules.py)）。画面の根拠表示は[捜査ボード](web/src/components/conclusion-board/ConclusionBoard.tsx)で確認できます。イベント形式と担当境界は[現行 API・SSE 契約](docs/api-sse-contract.md)を参照してください。
